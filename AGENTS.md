# Rules

Always apply skills from the project, in every session.

Avoid using new systems or Unity features that require a good grasp on Unity to understand.
Prefer simple solutions that follow the current code base patterns.

Break down tasks to extremely small tasks and propose the plan to me before proceeding.
Keep the plan proposal extremely short - preferably only bullet points with concrete files touched
and what will be done.

Each task must leave the project in a buildable, working state.
After each step, ask for my approval to continue before continuing.

# Code style

- Code that requires comments to understand is bad code. Comments is a remedy, not a solution.
- Avoid introducing new systems unless required. Use what's there if it makes sense. If it really should be a new system, run it by me first.
- Absolute minimal changes. Solve the goal, and only that, the simplest way.
